# authority_map

Status: proposed authority boundaries for later implementation. These do not reconstruct the missing mathematical specification or authorize implementation.

The user's described ordered three-domain contract and companion silent-failure checklist remain authoritative. Their exact local files have not been established. No external repository is classified as core.

## L0 — Source registry and baseline manifest

- Allowed inputs: local paths, file metadata, inspected bytes, paper identities, version declarations and explicit qualification evidence.
- Allowed outputs: source records, evidence hashes, unresolved items and source-selection records.
- Owns: provenance and qualification bookkeeping only.
- Prohibited: certifying a kernel from a plausible filename; equating a package version with a Git commit; treating a file listing as content validation.
- Failure propagation: unknown identity/version remains unknown; block dependent promotion, not unrelated inventory.

## L1 — Config and preset resolver

- Allowed inputs: frozen contract permissions once located, explicitly selected source profiles, presets and user overrides.
- Allowed outputs: fully resolved configuration, per-field origin, validated precedence and a reproducible configuration identity.
- Owns: allowed configuration resolution, not the definition of allowed mathematics.
- Prohibited: overriding kernel-owned fields; changing units, equations, probability meanings or veto rules; importing BC2's scientific defaults as the user's core.
- Failure propagation: invalid, conflicting, cyclic or unknown settings stop dependent execution before core evaluation. No fallback preset or model substitution.

## L2 — Source adapters and explicit preprocessing

- Allowed inputs: explicit artifacts, sample/producer/checkpoint identities, chain/residue/domain bindings, masks, units, frames and approved transformation declarations.
- Allowed outputs: typed evidence/input proposals, lossless mappings and transformation provenance.
- Owns: representation conversion and identity preservation.
- Prohibited: guessing chains, units, coordinate frames or probabilities; sorting ordered domains; collapsing samples; silently repairing inputs; emitting core outcomes.
- Failure propagation: required artifact/mapping failure blocks dependent admission; optional evidence becomes unavailable with a reason. No partial result disguised as complete.

## L3 — QC and audit

- Allowed inputs: artifacts, applicable check definitions, mappings and immutable results.
- Allowed outputs: check-specific findings and separately identified admission restrictions.
- Owns: integrity, provenance and scoped check findings.
- Prohibited: changing core status; clearing deterministic vetoes; interpreting unrun/unsupported checks as passes; transferring small-molecule checks to unrelated artifact types without evidence.
- Failure propagation: required QC failure prevents dependent admission/eligibility under an explicit rule. Optional check failure is recorded separately and cannot alter a computed core result.

## L4 — Authoritative geometry core

- Allowed inputs: only inputs permitted by the located frozen contract, preserving ordered domain identity, units and uncertainty.
- Allowed outputs: only that contract's mathematical outputs, derived fields, statuses and diagnostics.
- Owns: equations, deterministic veto precedence, probability prerequisites, result semantics, derived-field ownership and unit conventions.
- Prohibited: external overrides, probability evaluation forbidden by veto, unauthorized derived-field inputs and unversioned extensions.
- Failure propagation: exact behavior must come from the missing contract. Do not invent status labels, substitute zeros or infer permission to continue.

## L5 — Ranking and reporting

- Allowed inputs: immutable core results, separate QC findings and provenance-bearing auxiliary metrics.
- Allowed outputs: eligibility decisions under an approved definition, eligible rankings, excluded-result records and reports.
- Owns: explicitly defined ordering and presentation after eligibility.
- Prohibited: making an ineligible item eligible; score compensation for veto; representing Potts/ProteinMPNN energy, confidence or embeddings as core probability/status/derived fields.
- Failure propagation: missing required eligibility evidence means no eligible ranking; optional-score failure follows an explicit missing-value rule while preserving all source records.

## L6 — Campaign orchestration and persistence

- Allowed inputs: resolved configuration, qualified stage identities and explicit dependency graph.
- Allowed outputs: run/attempt manifests, scheduling state, logs and verified completed artifacts.
- Owns: execution and persistence state, kept separate from core and QC statuses.
- Prohibited: silent setting changes, substitute models, overwriting baseline records, accepting partial outputs or bypassing failure.
- Failure propagation: fail dependent stages; independent branches may continue with visible failure records. Resume must validate identity, relevant settings and artifact completeness rather than file existence alone.

## L7 — Notebook / Colab delivery

- Allowed inputs: explicit selected artifacts/configuration and calls to qualified interfaces.
- Allowed outputs: configuration preview, execution status, source-backed reports and exportable run bundles.
- Owns: interaction and presentation only.
- Prohibited: duplicate equations, hidden mutable state, implicit demo fallback, automatic substitution or retroactive status relabeling.
- Failure propagation: show precise failure/missing state; do not display stale previous-cell output as the current run.

## Future-extension lane

- Allowed inputs: immutable baseline input snapshots and separately specified experimental model/parameter contracts.
- Allowed outputs: separately versioned experimental records and semantically qualified comparisons.
- Owns: experimental model semantics only within its namespace.
- Prohibited: baseline write-back, default activation, reuse of baseline field names for different meanings, or promotion by model-generated prose alone.
- Failure propagation: experimental failure stays in the experimental record; the baseline result remains unchanged.
- Generalized tether/network models, sampled survival, empirical chi, conditional-joint alternatives and anisotropic/sampled densities enter only here unless the located baseline already exposes a compatible input contract. If chi is derived or fixed, an empirical estimate cannot be injected.

## Cross-layer invariant

Deterministic veto precedes permitted probability calculations and cannot be repaired by QC, ranking or orchestration. Audit status, execution status, core status and ranking eligibility remain separate. Exact enum values and null/omission conventions await the authoritative contract.
