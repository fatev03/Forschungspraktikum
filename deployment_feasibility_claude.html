⚙️ Where can you actually run this? Deployment feasibility for the 2026 folding & design stack

Companion to the model-comparison table. Same tools, but scored on can I run it rather than is it good. Three targets: a laptop with no dedicated GPU, Google Colab, and a Slurm cluster with GPUs up to B300.
💻 Laptop (assumed) No dedicated NVIDIA GPU. CPU inference or Apple-Silicon MLX only. Treated as an analysis and orchestration machine, not a compute node.
☁️ Colab (assumed) Free = T4, ~15 GB VRAM. Pro/Pro+ = L4 24 GB, sometimes A100 40/80 GB, never guaranteed. Max 12 h session, ~90 min idle disconnect, ephemeral disk, no persistent TB-scale databases.
🖥️ HPC (assumed) Slurm, mixed GPUs up to B300 (Blackwell Ultra, 288 GB). No root; Apptainer rather than Docker. Compute nodes may have no outbound internet. Shared scratch.
⚠️ The two findings that actually change your plan.
1. Your best GPU is your riskiest GPU. Blackwell (B200/B300, compute capability 10.x) is not a safe default for this software. AF3's docs specify CC 8.0+ and predate Blackwell; there is an open compatibility request against JAX. RFdiffusion3's own install tutorial warns that Lovelace/Blackwell "may require upgraded PyTorch nightly builds." Every JAX-based tool in this stack (AlphaFold2, ColabFold, ColabDesign, BindCraft, Germinal) inherits that risk, as does anything shipping custom CUDA kernels (PXDesign, Boltz-2's cuEquivariance path). Plan to run the JAX half of your pipeline on A100/H100/L40S partitions and save B300 for pure-PyTorch, long-context jobs.
2. MSA databases, not GPUs, are the real HPC install cost. AF2's full genetic DBs are ~2.6 TB; AF3's are ~252 GB compressed / ~630 GB uncompressed. If your compute nodes have no internet, the convenient --use_msa_server path fails and you must host these locally. Choosing MSA-free tools (ESMFold/ESMFold2, SimpleFold, RFdiffusion3, ProteinMPNN, SeedProteo) sidesteps the entire problem.

📐 The pattern in one paragraph

Feasibility in this field is not mainly about FLOPs. Three things decide it: (1) does it need an MSA database — that is a terabyte-scale, one-time institutional cost that no laptop or Colab session can absorb; (2) is the design budget above or below ~12 hours — that single number cleanly separates "Colab can do it" from "this is an array job"; and (3) is the licence a technical or a legal artifact — AF3's gated weights, PyRosetta, IgLM and SurfFold's missing licence file will each stop you more reliably than any VRAM limit.
Short version. The laptop is a control plane, Colab is a teaching and prototyping surface, and the HPC is where every real campaign runs. Do not try to make the first two do the third's job — but do use them deliberately, because both have a job that the cluster does badly.

💻 Laptop — orchestration, analysis, and hosted services

Run locally: ProteinMPNN, ipSAE + the pDockQ family, PepMLM, SimpleFold (if Apple Silicon)

All CPU-viable, all genuinely useful. ipSAE in particular is the single best-validated ranking improvement available — it beat ipTM, iPAE, actifpTM and pDockQ across 1,589 BindCraft/RFdiffusion designs — and it costs you a pip install numpy. Reranking a finished campaign on your laptop is real work.

Use hosted services for anything exploratory

The Protenix/PXDesign web server (free, no GPU, and the authors' own recommendation), Latent-X's free tier, ESM Atlas, and the AlphaFold Server. For "what does this target look like, is this epitope plausible" questions these beat waiting in a Slurm queue.

Treat the laptop as the pipeline driver

Write your submit scripts, parse results, and do all filtering/plotting here. Everything downstream of the GPU in this field is small-data.

☁️ Google Colab — prototyping and teaching, on Pro

What it is genuinely good for

ColabFold is the best folding experience on any platform, because it moves MSA search to a remote server and removes the 2.6 TB problem entirely. RFdiffusion3 is a surprise fit — ~3 GB GPU memory means it runs even on a free T4. The BindCraft and ColabDesign/RFdiffusion notebooks are the fastest way to understand what these pipelines actually do before you commit cluster hours to them. On Pro, Boltz-2 handles ~1,600 tokens on a 24 GB L4.

What kills you

The 12-hour ceiling and ~90-minute idle disconnect. A BoltzGen campaign wants 10,000–60,000 designs; an ESMFold2 design run is ~2 days per target; Germinal is 200–400 H100-hours. None of these survive contact with a Colab session. Ephemeral disk also means no persistent Foldseek index and no local MSA databases. And GPU allocation is never guaranteed, even on Pro — you cannot plan a deadline around it.

Verdict

Worth a Pro subscription as a learning and debugging environment. Never as production. If you catch yourself trying to checkpoint around the 12-hour limit, that is the signal to move to Slurm.

🖥️ Slurm HPC — the actual platform

Step 1 · Pick the epitope before you pick the model

You are targeting surface proteins, so the extracellular topology determines what is even designable. This project already has a DeepTMHMM workflow on the cluster — run it first and design only against confidently extracellular regions. Note too that PolyFold found OpenFold3 essentially fails on membrane proteins (DockQ ≈ 0), which is a warning about the whole model class on this target type.

Step 2 · Generate — BoltzGen as primary, RFdiffusion3 as the cheap workhorse

BoltzGen (MIT, pip install boltzgen) covers minibinders, VHHs and macrocycles in one model, parallelises with --devices, and reported nanomolar binders for 66% of 9 novel targets. Smoke-test with --num_design 50, then run 10,000–60,000 as a Slurm array. RFdiffusion3 is worth installing regardless: ~3 GB VRAM and ~10× faster than RFd2 means you can run it opportunistically on whatever GPU is free. Keep BindCraft as your reference baseline — it is the pipeline with published, X-ray-confirmed, independently-scrutinised numbers.

Step 3 · Filter hard — this is where the leverage is

AF2-IG re-prediction, then rank with ipSAE (practical cutoff ipSAE_min > 0.61), cross-checked with Boltz-2's affinity module. PXDesign's result that simply re-ranking existing RFdiffusion designs by a better confidence metric raises hit rates on every target is the cheapest available improvement in the whole pipeline. Budget real compute for filtering, not just generation.

Step 4 · Partition your GPUs by framework, not by size

Send JAX jobs (ColabFold, BindCraft, AF2-IG, Germinal) to A100/H100/L40S. Send pure-PyTorch jobs (BoltzGen, RFdiffusion3, ESMFold2, Boltz-2, Chai-1) to the B300s, where the 288 GB of HBM buys you long targets and large batches. Validate one small job per tool per GPU generation before submitting an array — a 2,000-job array that fails on sm_100 at minute one is an expensive way to learn this.

Step 5 · Close the loop experimentally

Adaptyv's BenchBB is the only fixed-target, fixed-budget, independent wet-lab benchmark in the field, with an API and open results under ODbL. Their Nipah G round — 1,196 community designs → 111 binders, under 10% — is the number to calibrate against, not the 66–88% headline rates.

🎯 If you only install four things

  • BoltzGen — MIT, one pip command, covers the formats you need, strongest credible reported rates.
  • RFdiffusion3 — ~3 GB VRAM, ~10× faster than RFd2, Apptainer-able, training code released.
  • ipSAE — numpy only, best-validated filter, works on Boltz/Chai/AF output.
  • BindCraft — your baseline for sanity-checking everything above against published wet-lab numbers.
That stack is MIT/open end to end, needs no gated weights, no PyRosetta licence for the first three, and no terabyte-scale MSA database. Add Boltz-2 when you want affinity estimates, and OpenGerminal if you move into nanobody formats.

🧨 Blackwell / B300 — the thing to test before you trust

Blackwell-generation cards use compute capability 10.x (B200/B300) and 12.0 (RTX 50-series), which most of this software predates. Concretely:
  • JAX stack (AlphaFold2, AlphaFold3, ColabFold, ColabDesign, BindCraft, AF2-IG, Germinal) — AF3's docs specify CC ≥8.0 and do not mention Blackwell; there are open compatibility issues against both AlphaFold and AlphaFold3 for Blackwell cards. Needs a recent jax[cuda12] with matching cuDNN and PTX; expect to pin versions.
  • PyTorch stack — generally fine on recent versions, but RFdiffusion3's own tutorial warns Lovelace/Blackwell "may require upgraded PyTorch nightly builds with matching CUDA versions."
  • Custom CUDA kernels (PXDesign, Boltz-2's cuEquivariance path, various Triton kernels) — the highest-risk category. They either need recompiling for sm_100 or fall back silently to a slower path. Time one small job and compare against an H100 before believing your throughput numbers.
  • PTX JIT issues have been reported on Blackwell with CUDA 12.8/12.9 toolkits — if you see missing libnvptxcompiler errors, that is this, not your code.
Practical rule: the newest GPU is the least compatible one. Treat B300 as a capacity resource for validated jobs, not as your development target.

🌐 No internet on compute nodes?

This one flag flips the feasibility of half the table, because it kills every --use_msa_server path. Mitigations in order of preference:
  • Prefer MSA-free models. ESMFold, ESMFold2, SimpleFold, RFdiffusion3, ProteinMPNN, BoltzGen's generator all need no genetic database. This is the single biggest simplification available to you.
  • Pre-compute MSAs on the login node in a separate job stage, then pass them to the GPU job as files. Works for Boltz-2, Chai-1, AF3.
  • Host the databases only if you truly need AF2/AF3-grade MSAs: ~2.6 TB for AF2's full set, ~630 GB uncompressed for AF3's. Ask for a project allocation, not home quota.
  • Cache weights explicitly. Most of these tools download checkpoints on first run. Do that once on a login node; use flags like RFd3's --checkpoint-dir and set HF_HOME to shared scratch.

📦 No root, Apptainer only

Less of a problem than it used to be. RFdiffusion3/foundry, RFdiffusion2 and PXDesign all publish container images, and apptainer build x.sif docker://… converts them without root. Everything else in the recommended stack is plain pip. Two habits worth keeping: build the .sif once on the login node and store it in shared scratch, and pin exact versions — this ecosystem breaks compatibility quickly.

⚖️ Licence blockers, ranked by how often they stop people

  • PyRosetta — needed by BindCraft and Germinal. Free for academics but requires registration and a site install. OpenGerminal exists specifically to remove this dependency.
  • AlphaFold2 multimer weights — CC BY-NC-SA. BindCraft is MIT but inherits this, so BindCraft output is not commercially clean.
  • AlphaFold3 weights — application-gated, granted at DeepMind's discretion, non-commercial terms. Cannot be redistributed, which is why there is no legitimate AF3 Colab.
  • IgLM — needed by original Germinal.
  • SurfFold — ships with no licence file at all, which defaults to all rights reserved. Evaluate, don't build on it.
  • Clean end to end: BoltzGen (MIT), Boltz-2 (MIT), ESMFold2 (MIT), Protenix/PXDesign (Apache-2.0), Chai-1 (now stated Apache-2.0 for weights), ProteinMPNN, RFdiffusion3, ipSAE.

⏱️ Rough compute budget for one binder campaign

Order-of-magnitude only, from the numbers the tools themselves state:
  • BindCraft — 300–3,000 trajectories per target; a single GPU-days-scale job per target.
  • BoltzGen — 10,000–60,000 designs recommended upstream of filtering; embarrassingly parallel, so this is an array job sized by your allocation rather than by wall clock.
  • Germinal — the most honest published figure in the table: ~200–400 H100-hours for ~200 successful designs, ~1 success per GPU-hour.
  • ESMFold2 design mode — ~2 days generation plus <1 day scoring per target. Note the shape of that cost: the model is fast per fold, but design is 150 gradient steps (forward + backward) per design, so ~450 forward-equivalents each, times thousands of designs.
  • Filtering — plan for this to be a similar order of magnitude to generation, not an afterthought. It is where the published hit rates come from.
A reasonable first ask: one target, BoltzGen + RFdiffusion3 generation, AF2-IG + ipSAE filtering, ~20–100 designs ordered from Adaptyv. That is a few hundred GPU-hours and a real result.
